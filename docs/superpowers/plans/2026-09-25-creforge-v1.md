## Implementation notes

- **Events instead of a dense matrix.** For each account, the engine draws one of six
  events and derives the destination state from it. This is the same as the spec's
  `P` matrix, but structural zeros (no jumping more than one bucket) hold by
  construction instead of relying on matrix entries.
- **State is derived from months-in-arrears.** For `C` and `D1`..`D5`,
  `state = min(mia, 5)`, so DPD and arrears can't drift apart.
- **Money is Float64 rounded to 2 dp.** (0.3 added an exact `Decimal(18, 2)` option;
  measurement showed no real speed cost.)
